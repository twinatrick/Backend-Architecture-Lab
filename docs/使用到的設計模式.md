## 一、 建立型模式 (Creational Patterns)

### 1. 單例模式 (Singleton Pattern)
- **設計動機**：確保核心服務、資料存取元件與設定物件在應用程式生命週期中僅存在單一實例，節省系統資源並維持狀態一致性。
- **原始碼實作**：
  - **Java**：Spring Framework IoC 容器所託管的所有 Bean（Controller, Service, DataAccess 等）預設皆為 Singleton 作用域。
  - **Python**：`backend-ai-py/services/traditional_chinese_converter.py` 的 `traditional_chinese_converter` 實例與 `backend-ai-py/config.py` 中的 `settings`。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Service.Impl.UserService`
  - `com.example.BackendArchitectureLab.Config.BloomFilterProperties`

### 2. 建造者模式 (Builder Pattern)
- **設計動機**：處理屬性眾多的 Entity、VO、DTO 與非同步 Event 物件，提供清晰且具可讀性的流暢建構語法（Fluent API），並保證物件不可變性（Immutability）。
- **原始碼實作**：全面透過 Lombok `@Builder` 與 `@NoArgsConstructor` / `@AllArgsConstructor` 達成。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Entity.CompensationOutboxEvent`
  - `com.example.BackendArchitectureLab.Vo.Kafka.CompensationEvent`
  - `com.example.BackendArchitectureLab.Vo.JobPostingVo`
  - `com.example.BackendArchitectureLab.Vo.UserVo`

### 3. 規格工廠模式 (Specification Factory Pattern)
- **設計動機**：動態組合 JPA Criteria 查詢條件，避免在 Service 層拼接 SQL/JPQL 字串。
- **原始碼實作**：以靜態工廠方法回傳 `Specification<T>` Lambda 表達式。
- **典型類別**：
  - `com.example.BackendArchitectureLab.DataAccess.specification.UserSpecification`
  - `com.example.BackendArchitectureLab.DataAccess.specification.JobPostingSpecification`
  - `com.example.BackendArchitectureLab.DataAccess.specification.AlertCheckLimitSpecification`
  - `com.example.BackendArchitectureLab.DataAccess.specification.SkillSpecification`

## 二、 結構型模式 (Structural Patterns)

### 4. 組合模式 (Composite Pattern)
- **設計動機**：將多種不同爬蟲機制（高效的 Jsoup 靜態爬蟲與支援動態渲染的 Selenium 爬蟲）組合成統一抽象介面，讓呼叫端無需關心底層策略切換。
- **原始碼實作**：`CompositeJobCrawler` 實作 `IJobCrawler` 介面，內部組合並自動調度 `JsoupJobCrawler` 與 `SeleniumJobCrawler`。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Crawler.IJobCrawler`（抽象介面）
  - `com.example.BackendArchitectureLab.Crawler.Impl.CompositeJobCrawler`（組合協調者）
  - `com.example.BackendArchitectureLab.Crawler.Impl.JsoupJobCrawler`（子組件）
  - `com.example.BackendArchitectureLab.Crawler.Impl.SeleniumJobCrawler`（子組件）

### 5. 代理模式 (Proxy Pattern) / 切面裝飾 (AOP Pattern)
- **設計動機**：將跨切面關注點（如 Controller 三層權限檢查、分散式交易管理 `@Transactional`、日誌記錄）與商業邏輯解耦。
- **原始碼實作**：透過 Spring AOP `@Around` 環繞通知動態攔截請求，解析 `@RequirePermission` 註解並進行權限驗證。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Aop.PermissionCheck`
  - `com.example.BackendArchitectureLab.Annotation.RequirePermission`

### 6. 適配器與物件轉換器模式 (Adapter / Object Mapper Pattern)
- **設計動機**：嚴格實施資料隔離規範，Controller 嚴禁直觸 Entity，需透過 Mapper 進行 Entity ↔ VO 雙向轉換。
- **原始碼實作**：透過 MapStruct 的 `@Mapper(componentModel = "spring")` 產生編譯期高效的型別轉換器。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Mapper.UserMapper`
  - `com.example.BackendArchitectureLab.Mapper.ProjectMapper`
  - `com.example.BackendArchitectureLab.Mapper.SkillMapper`
  - `com.example.BackendArchitectureLab.Mapper.JobPostingMapper`
  - `com.example.BackendArchitectureLab.Mapper.AquarkDataMapper`

### 7. 門面模式 (Facade Pattern)
- **設計動機**：當商業流程涉及跨多個 DataAccess、Redis 快取、Kafka 事件發布與 Feign Client 呼叫時，由 Service 提供高階、單一職責的統一入口。
- **原始碼實作**：
  - `com.example.BackendArchitectureLab.Service.Impl.ProjectUserBindingService`（統一封裝專案成員綁定、技能同步與分散式補償事務發起）
  - `com.example.BackendArchitectureLab.Service.Impl.AuthService`（統一封裝驗證、Token 簽發與權限快取載入）

### 8. 防腐層模式 (Anti-Corruption Layer - ACL / DAO Pattern)
- **設計動機**：隔離底層 Spring Data JPA Repository 與資料庫實體細節，嚴禁 Service 層直接存取 EntityManager。
- **原始碼實作**：以 `IDataAccess` 介面搭配 `DataAccessImpl` 封裝所有實體持久化邏輯與動態 Specification。
- **典型類別**：
  - `com.example.BackendArchitectureLab.DataAccess.IUserDataAccess` / `UserDataAccessImpl`
  - `com.example.BackendArchitectureLab.DataAccess.IProjectDataAccess` / `ProjectDataAccessImpl`
  - `com.example.BackendArchitectureLab.DataAccess.ICompensationEventLogDataAccess` / `CompensationEventLogDataAccessImpl`

## 三、 行為型模式 (Behavioral Patterns)

### 9. 策略模式 (Strategy Pattern)
- **設計動機**：將可互換的演算法或業務處理邏輯獨立封裝，支援開閉原則（OCP），新增策略無需修改呼叫端。
- **原始碼實作**：
  1. **補償回滾策略**：`CompensationStrategy` 介面搭配多個具體策略，依 Kafka 補償事件的 `CompensationAction` 動態路由。
     - `com.example.BackendArchitectureLab.Service.Strategy.CompensationStrategy`（策略介面）
     - `com.example.BackendArchitectureLab.Service.Strategy.ProjectMemberSkillsRebindCompensationStrategy`（具體補償策略）
  2. **爬蟲抓取策略**：依目標網頁性質選擇靜態 HTML 解析或動態瀏覽器渲染。
- **呼叫流程**：`CompensationEventProcessor` → 委派 `ICompensationExecutionService` → 依 Action 匹配對應 `CompensationStrategy`。

### 10. 範本方法模式 (Template Method Pattern)
- **設計動機**：定義骨架流程，並允許特定子系統覆寫特定步驟。
- **原始碼實作**：
  - `com.example.BackendArchitectureLab.Aop.LocalPermissionValidator` 定義驗證框架與預設遠端 Feign 呼叫。
  - `com.example.BackendArchitectureLab.Service.Impl.LocalPermissionValidatorImpl` 在 IAM 模組中覆寫 `validate()` 改走本機查詢，避免微服務自身發起循環網路呼叫。

### 11. 觀察者模式 / 發布-訂閱模式 (Observer / Pub-Sub Pattern)
- **設計動機**：實現系統各微服務間的非同步解耦與即時訊息廣播。
- **原始碼實作**：
  - **Kafka 訊息佇列**：
    - 發布者：`com.example.BackendArchitectureLab.Service.Impl.AlarmKafkaPublisher`、`com.example.BackendArchitectureLab.Timer.CompensationOutboxWorker`
    - 訂閱者：`com.example.BackendArchitectureLab.Service.Impl.KafkaConsumerService`、`com.example.BackendArchitectureLab.Service.Impl.CompensationConsumer`
  - **WebSocket 即時推播**：`com.example.BackendArchitectureLab.WebSocket.AlarmWebSocket`

### 12. 規格模式 (Specification Pattern)
- **設計動機**：將查詢條件物件化，支援鏈式調用（`where(spec1).and(spec2).or(spec3)`）。
- **原始碼實作**：實作 Spring Data JPA 的 `Specification<T>` 介面。
- **典型類別**：
  - `com.example.BackendArchitectureLab.DataAccess.specification.UserSpecification`
  - `com.example.BackendArchitectureLab.DataAccess.specification.AlertCheckLimitSpecification`
  - `com.example.BackendArchitectureLab.DataAccess.specification.SkillSpecification`

## 四、 微服務與分散式架構模式 (Distributed & Microservice Patterns)

### 13. 事務發件匣模式 (Transactional Outbox Pattern)
- **設計動機**：解決分散式架構下「本地資料庫更新」與「發送 Kafka 訊息」的雙寫一致性問題（Dual-Write Problem）。
- **原始碼實作**：在同一個本地 ACID 交易內將商業資料與 `CompensationOutboxEvent` 一併寫入 DB，再由背景定時排程非同步推送到 Kafka，發送成功後更新交付狀態。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Service.Impl.CompensationOutboxServiceImpl`
  - `com.example.BackendArchitectureLab.Timer.CompensationOutboxWorker`
  - `com.example.BackendArchitectureLab.Entity.CompensationOutboxEvent`

### 14. 補償交易模式 / Saga 模式 (Compensating Transaction / Saga Pattern)
- **設計動機**：在微服務跨資料庫場景下，放棄重量級 2PC/XA 分散式事務，改以最終一致性（Eventual Consistency）與非同步補償機制復原資料。
- **原始碼實作**：`CompensationEventProcessor` 接收失敗事件，解析快照 payload 並觸發對應的還原補償動作。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Service.CompensationEventProcessor`
  - `com.example.BackendArchitectureLab.Service.Impl.CompensationRestoreService`

### 15. 冪等接收者與租約防護模式 (Idempotent Receiver & Fencing Token Pattern)
- **設計動機**：在 Kafka At-Least-Once 語意下防止重複消費，並防止 Consumer 因 GC 暫停導致的舊租約腦裂覆寫。
- **原始碼實作**：以 `eventId` 唯一鍵進行原子領取（Claim），並搭配單調遞增的 `fencingVersion` 與 `ownerId`。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Service.CompensationEventProcessor`
  - `com.example.BackendArchitectureLab.Timer.CompensationLeaseReclaimer`

### 16. 死信佇列模式 (Dead Letter Queue / DLT Pattern)
- **設計動機**：隔離毒丸訊息（Poison Pill）與永久不可重試的異常，避免阻塞佇列並保留現場供維運排查。
- **原始碼實作**：非重試型異常直接標記 `DEAD` 並拋出例外由 Kafka DLT 接管。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Service.CompensationEventProcessor`
  - `com.example.BackendArchitectureLab.Exception.CompensationDeadEventException`

### 17. 讀寫責任分離模式 (CQRS Pattern)
- **設計動機**：將變更狀態的 Command 與讀取資料的 Query 介面徹底分離，提高內聚性並利於後續擴展獨立讀寫最佳化。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Service.IFunctionCommandService` / `IFunctionQueryService`
  - `com.example.BackendArchitectureLab.Service.IProjectCommandService` / `IProjectQueryService`
  - `com.example.BackendArchitectureLab.Service.IAquarkDataCommandService` / `IAquarkDataQueryService`

### 18. 布隆過濾快取防護模式 (Bloom Filter Cache Defense Pattern)
- **設計動機**：在訪問 Redis 與 PostgreSQL 之前，透過機率型資料結構快速判定 Key 是否存在，阻絕惡意或無效請求導致的快取穿透（Cache Penetration）。
- **原始碼實作**：基於 Redisson 分散式布隆過濾器封裝。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Service.Impl.BloomFilterService`
  - `com.example.BackendArchitectureLab.Config.BloomFilterInitializer`

### 19. 宣告式 REST 客戶端 (Declarative REST Client - OpenFeign Pattern)
- **設計動機**：以宣告式介面取代手動 HttpClient 呼叫，實現微服務間的 RPC 呼叫與負載均衡。
- **典型類別**：
  - `com.example.BackendArchitectureLab.Feign.PermissionCheckFeignClient`

## 五、 Python AI 服務模式 (Python Service Patterns)

### 20. 降級備援模式 (Fallback / Graceful Degradation Pattern)
- **設計動機**：當外部依賴的 AI 模型服務（如遠端 GPT-SoVITS TTS 服務）離線或逾時，自動無縫降級至本地離線輕量引擎，維持服務高可用性。
- **原始碼實作**：`backend-ai-py/services/tts_service.py` 捕捉外部連線異常後，自動調用 `FallbackTtsEngine`（基于 sherpa-onnx VITS 離線模型）。
- **典型類別**：
  - `backend-ai-py/services/fallback_tts_engine.py` (`FallbackTtsEngine`)
  - `backend-ai-py/services/tts_service.py`

### 21. 子進程環境隔離模式 (Subprocess Environment Isolation Pattern)
- **設計動機**：解決多模型環境（如 PyAnnote 語者分離與 SenseVoice/Whisper）在同一個 Python 執行環境下發生的 CUDA 版本與 C++ DLL 衝突問題。
- **原始碼實作**：透過跨 Conda 環境子進程動態調度，以 JSON 檔案交換語者標註中繼資料。
- **典型模組**：
  - `backend-ai-py/services/diarization_service.py`
  - `backend-ai-py/services/stt_engine.py`
