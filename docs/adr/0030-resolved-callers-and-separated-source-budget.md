# 無歧義生產呼叫端反證與分離原始碼預算

狀態：Accepted。承接 ADR-0027 與 ADR-0029，經逐題訪談確認以下查證界線。

## 決策與取捨

- 將「生產呼叫端存在性」與「入口可達性」分為獨立規則主張。取得一個無歧義的生產呼叫即可否定「無生產呼叫端」，即使其他檔案未讀、語法未支援或後續預算不足，也不推翻已成立的反證。
- 反向證明仍須完整必要搜尋與規則適用性；未解析的使用方式、未知來源集、多載、方法參照、反射、未知繼承或讀取缺失都不可當作未使用。首版負向範圍限 Repository 明確宣告、非框架入口或履約的方法，且只描述靜態來源，不宣告執行時不可達。
- 接收者須解析至完整型別，目標宣告須唯一，並驗證支援範圍內引數型別。不把名稱或參數個數相同視為符號解析；歧義候選不妨礙繼續找另一個充分反證。
- 原始碼讀取／解析與送模型上下文分別計費。所有批次、拆批與靜態階段共享固定 Repo／SHA／路徑的讀取與解析結果；首版單檔上限 2 MiB、全場唯一版本源碼 32 MiB、全場 15 分鐘。模型額外上下文仍維持自身上限。
- 錯誤方法名稱或可見性可由獨立事實查證器否定；同一疑點中的業務主張仍須保留並個別審核資格，不能將方法引用誤述當成業務流程安全證明。

選擇提前結案的充分反證，而非強迫每次完整掃描全部來源，可避免已知呼叫仍被資源上限誤擋；代價是必須明確記錄證明方向與能力邊界。未採用只放大模型上下文上限的方案，因為完整程式檔案不是全數都需送進模型。

## 首版實作界線

呼叫解析採有限詞法／結構模型，不執行 PR 程式。正向證明限明確欄位接收者、唯一介面宣告與可精確辨識的呼叫方法參數型別；局部資料流、隱含泛型轉換、自訂繼承及 Java text block 等未知情況維持 `INCONCLUSIVE`。測試來源不參與生產存在性證明；未知語言或來源集阻止負向證明。

本決策不移除 Fail-Closed、不退回舊引擎、不自動降低人工簽核要求。部署仍須先通過反例測試、固定 PR 快照回歸與正式閘門／稽核／報告一致性驗證；合入受信任主要分支後另驗 CI，不以強迫全綠取代證據。
