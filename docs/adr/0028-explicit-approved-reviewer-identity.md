# 28. 人工主張裁定採明確核准審核者身分

Date: 2026-10-30
Status: Accepted

## Context

ADR 0027 原要求以主要分支合併資格判定人工主張裁定授權。
專案負責人已確認改由其直接核准審核者名單：能判定誤報不必同時具有合併資格。
另須區分兩個問題：誰可以裁定，以及保存裁定的紀錄能否被未授權修改。
不能為了解決前者而省略後者的保護。

## Decision

- 取代 ADR 0027 的「主要分支合併資格」授權條件，採受信任檢出中的明確核准名單。
- 第一版僅核准專案負責人 `twinatrick`，GitHub 固定使用者 ID 為 `130625933`。
- 名稱只供識別；GitHub API 回傳的固定 ID 才是授權依據，留言 ID 身分亦須一致。
- PR 提議修改名單，不會使其在合併至受信任預設分支前取得資格。
- 紀錄保存固定審核者 ID 與明確裁定授權，不以布林值偽稱取得合併權限。
- 名單納入查證版本摘要；名單修改使舊主張識別碼失效。唯讀消費端亦排除已撤銷資格者。
- API、設定缺漏或格式不符均拒絕授權；不回退至管理員、write 權限或 LLM 判斷。
- 裁定仍綁定 PR、Base/Head SHA、規則版本及具體主張；高風險簽核獨立。
- 保留裁定分支防竄改要求與預設影子模式，不因這項決策降低保存保護或啟用正式閘門。

## Consequences

- 不再為了裁定資格推導複雜的主要分支保護與合併權限。
- 專案負責人必須維護名單，新增／撤銷資格須走受信任設定變更流程。
- 舊的合併授權紀錄格式不自動升格為核准審核者紀錄，格式不相容時拒絕讀取。
- 個人 Repository 的單一 writer 裁定分支保護問題仍須另行解決，不能宣稱已完成部署。
