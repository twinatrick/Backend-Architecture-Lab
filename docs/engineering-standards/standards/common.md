# 共通既有基準

狀態：`0.2.0` 正式版本。`0.1.0` 的交集基準保留於下表；本版依賴原則補充見下節。新增要求不是舊版既有交集，亦不自動升級消費端鎖定快照。完整措辭及例外見各 Profile。

| 識別碼 | 既有共通要求 | 來源定位 |
| --- | --- | --- |
| C-01 | 保持單向分層及職責邊界，禁止 View／Controller 繞過業務層 | 後端規範 §1；前端規範 §1 |
| C-02 | 存取需遵守專案權限機制，不能自行繞過 | 後端規範 §2；前端規範 §1.2 第 3 項 |
| C-03 | 跨層資料依明確契約傳遞，不暴露資料儲存實作或任意抹除型別 | 後端規範 §1.3、3.2；前端規範 §1.1、2.2 |
| C-04 | 非預期例外不得靜默吞掉；依層級回報或轉成適當錯誤 | 後端規範 §4.4、8.4；前端規範 §1.2 第 4 項 |
| C-05 | 單一職責、避免重複、保持簡單、不預留無需求設計、移除死碼並遵守 Boy Scout Rule | 後端規範 §5；前端規範 §4 |
| C-06 | 溝通、文件、註解與面向使用者訊息遵守繁體中文要求 | 兩端 AGENTS 語言規則；後端規範 §3、4.3；前端規範 §3.2 |
| C-07 | 提交前完成專案要求的規範與品質檢查，不因共通化而降低門檻 | 兩端 AGENTS；後端規範 §10；前端規範 §5 |
| C-08 | 未獲明確指示不可自行 commit／push；機密環境檔不得納入 Git，提交前檢查日誌及暫存文件 | 兩端 AGENTS Git 規則 |
| C-09 | 執行前優先讀取專案 `.run` 設定；不得把本機設定內容搬入公開文件 | 兩端 AGENTS 環境規則；前端規範 §1.2.2 |

共通整理不改寫技術細節：後端服務邊界不等同前端目錄、前端的型別限制不直接套用 Java，且後端的整套 SOLID 檢查表不因此變成前端新增條文。測試工具、覆蓋率、警告等級與執行緒限制仍依 Profile，而不是取兩端門檻的交集。

來源原文及代理執行指南若同一情境有互斥要求，維持待裁決，不從摘要自行推導勝者。

## 0.2.0 依賴原則補充

本節補充 C-01 與 C-05，適用前後端，屬於 `0.2.0` 的新增內容，不屬於 `0.1.0`。本版治理門禁已通過；消費端須經獨立採用程序更新鎖定快照，不因文件修訂或本版發布而自動升版。

| 識別碼 | 共通要求 | 適用與驗證 |
| --- | --- | --- |
| C-10 ADP 無環依賴 | 元件、模組及同層元件的原始碼依賴不得形成直接或間接循環；執行期互動另依 Profile 檢視，不把呼叫圖、型別圖及資料關聯圖混為一談 | 明確列出受檢元件、邊的定義與完整循環路徑；不能僅憑單一 import 或雙向訊息判定違規 |
| C-11 SDP 穩定依賴 | 依賴應朝向較穩定的契約與元件；穩定指依賴關係所形成的變更阻力，不等同近期修改次數少、目錄較底層或沒有外部依賴 | 審查被依賴者、對外依賴、契約責任與變更波及範圍；共用元件不得反向綁定特定頁面或業務編排實作 |
| C-12 SAP 穩定抽象 | 承擔穩定擴充邊界的元件，應以適當抽象契約隔離易變實作；抽象由核心需求／消費者語意定義，不洩漏供應商細節 | 與 DIP、KISS、YAGNI 一起審查；不要求每個類別、純工具或資料型別都新增 Interface，也不以介面數量當合規門檻 |

### 解耦與審查邊界

- 可採共用職責抽離、上提編排或依賴反轉；事件僅在契約、執行時機、錯誤傳遞及一致性可交代時使用。改成事件或延遲載入不代表自動消除耦合。
- 分開描述「原始碼依賴」與「執行期控制流程」：Infrastructure 實作核心定義的 Port 時，執行期可由核心呼叫實作，但原始碼仍由實作依賴核心契約。
- 不為套用原則強制改成 DDD 四層、取消後端既有 Service 介面，或讓前端新增 Java 式 Interface／Impl 成對樣板。
- ADP／明確邊界違規須有可重現路徑；SDP／SAP 的設計疑慮若缺乏具體影響證據，先列建議，不以「不夠抽象」直接阻擋。檢查工具是否自動執行，依各專案實際配置另行驗證。
